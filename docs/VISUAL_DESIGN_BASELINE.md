# 球搭子｜视觉设计基线（Canonical UI Baseline）

> **状态：长期有效 / 前端设计强约束**
>
> 本文件是「球搭子」H5 后续页面、组件与交互视觉实现的默认设计依据。新增页面、重构页面、AI/Codex 生成前端代码前，应同时阅读 `PRODUCT_BASELINE.md`、`INTERACTION_BASELINE.md`，并结合当前已有页面与 `src/styles.css` 判断实现方式。
>
> 优先级：**功能与业务规则正确 > 产品/交互基线 > 本视觉基线 > 当前已验证的组件/页面模式 > 早期视觉 Demo。**

## 1. 产品视觉定位
「球搭子」是一款给真实网球爱好者使用的、轻松但认真、好看但不过度装饰、可以真正组织和记录一场比赛的移动端赛事工具。核心气质：轻松 / 现代 / 克制 / 明亮 / 低饱和 / 有网球感 / 生活方式感 / 移动端优先 / 信息清晰。

## 2. 当前产品的设计原则
### 2.1 功能先于装饰
页面首先回答：我在哪里、最重要的信息是什么、下一步做什么。
### 2.2 信息密度
高于纯生活方式 App，低于专业赛事后台；复杂业务通过层级和渐进展示解决。
### 2.3 一页一个主要动作
一个页面原则上只有一个最明显的 Primary Action。
### 2.4 人优先于账号，赛事优先于字段
不要把数据库结构直接翻译成 UI。
### 2.5 展示优先，编辑按需进入
详情默认优先可读，编辑通过明确入口进入。
### 2.6 卡片代表实体
点击实体卡片默认进入详情；编辑、邀请、删除、报名等是明确动作。
### 2.7 空状态不改变页面职责
空状态可引导下一步，但不能越权承担其他一级页面的主功能。
### 2.8 权限状态必须可感知但不能污名化
公开/私有、可管理/只读等状态应有一致视觉提示，但“受限”不等于“禁用”。私有内容不要大面积灰掉、黑化或做成错误态。

## 3. 色彩体系
保留暖米白 + 鼠尾草绿 + 灰蓝 + 红土橙方向。私有/受限状态使用同一低饱和体系里的暖灰、石灰、低饱和橄榄灰，不另造高警告色。

## 4. 排版与空间
Mobile first，默认单列；稳定左右边距与安全区；触摸目标建议至少约 44px；长页面自然纵向滚动；不为多放内容压缩字体和间距。中英文都按真实文案长度设计，不以中文能放下一行作为 English 可用的依据；375/390/430px 下标题、按钮、Tab、Chip、Badge、Sheet 和动作栏必须允许合理换行/收缩/堆叠，不得靠缩小到不可读解决。

## 5. 卡片与容器
卡片承载同一语义单元的信息。推荐适中圆角、浅背景、轻边框、极轻阴影、充足内边距。禁止厚重投影、强悬浮、高对比描边、卡片套卡片和大量玻璃拟态。

## 6. 网球图形语言
使用抽象、几何、克制的球场线、圆/圆弧、轨迹/落点、对阵连接线、简化球体。

## 7. 图标
简洁、线性、圆润、统一线宽；关键操作仍应有文字。

## 8. 按钮与操作层级
主按钮明显但不厚重；次级操作降级；多个同级动作优先 Action Sheet / Bottom Sheet。移动端多动作区域必须遵守 `INTERACTION_BASELINE.md` 的按钮防碰撞规则。

## 9. Bottom Sheet / 弹层
Bottom Sheet 是辅助操作容器，不是第二个完整页面。

## 10. 核心页面专项规则
### 10.1 赛事大厅
赛事大厅只负责发现赛事。公开赛事卡优先回答：什么比赛、谁组织、什么水平、哪个城市、什么时候、什么赛制、多少人、当前状态。

**公开赛事与私有赛事必须在整张卡片的视觉语言上可一眼区分，不能只改两个文字。**

公开赛事保持更开放、信息充分的常规赛事卡。私有赛事发现卡使用克制的“受限感”：
- 明确锁图标 + “私有赛事”胶囊标签；
- 卡片底色、边框和顶部强调条使用比公开赛事更收敛的暖灰/低饱和中性色；
- 不展示组织者头像、参与者、具体时间、具体场地、报名人数、费用；
- 用独立的隐私说明区替代被隐藏的信息，例如“时间、具体场地与参与者仅向受邀球友开放”；
- 可以保留赛事名称、城市、水平、单/双打、赛制和状态，让卡片仍具有发现价值；
- 不把私有赛事做成 disabled/error 风格，用户仍可点击进入受限预览。

视觉差异只是状态解释，不能代替后端数据脱敏和权限控制。

### 10.2 我的赛事
强调“我创建/实际报名参加的赛事”和当前进度，不复制大厅全部筛选逻辑。

### 10.3 球搭子们
强调真实用户关系。我的球搭子与临时球搭子分开呈现，不使用“正式球搭子”。临时球搭子前台不展开完整战绩价值。

### 10.4 我的 / 我的打球档案
“我的”是个人入口，不做 Dashboard。头像昵称编辑与打球档案编辑明确区分。

### 10.5 我的战绩
与“我的赛事”严格区分。

### 10.6 报名 / 选择参赛者
核心是“选择这次谁参赛”，本人、真实球搭子、临时球搭子清楚区分。双打围绕一个两人 Entry 设计。

### 10.7 实时计分
明亮、快速、户外可读、大点击区域；禁止黑底电竞直播风格。

### 10.8 排名
兼顾荣誉感和可读性，不做 Excel 化或电竞排行榜。

### 10.9 淘汰签表
首先是信息图；移动端允许横向滑动、分轮或卡片式 bracket，禁止缩小到不可读。

### 10.10 赛事相册 / 参与赛事相册
照片应保留“比赛结束后的纪念感”，不能因为安全要求把主视觉做成纯灰块或无法识别的重度模糊图。默认展示清晰度适合页面浏览的**受保护水印预览**，水印应可感知但不遮挡主要人物；可包含赛事名称、日期/赛果等既有赛事上下文。

赛事页面按多张 source photo 卡片展示。赛事创建人/organizer 可以继续上传并逐张删除赛事源照片；删除是明确危险动作，必须与查看操作拉开层级并二次确认，说明会从赛事相册真正删除该源照片、阻止未来新的导入，但不会删除参赛者此前已成功保存的个人副本。实际参赛者只有查看和“加入我的参与赛事相册”动作，不出现赛事源上传、替换或删除管理入口。

高清原图查看是 organizer / actual participant 的次级受控动作。使用线性眼睛图标 + 必要文字/无障碍标签，放在图片附近但不抢占赛事主操作；点击后进入明确的高清查看状态，关闭后回到水印预览。无权限用户不展示照片内容，不使用“先显示模糊图再告诉你无权限”的诱导设计。

“我的 → 参与赛事相册”只展示本人主动加入并已经形成独立个人资产的照片，可按赛事上下文分组。个人照片的“移出我的相册”是次级危险动作，确认文案必须明确“只删除我的个人副本，不影响赛事源照片和其他参赛者”。“设置与隐私”只提供参与赛事相册整体 `仅自己可见 / 搭子可见` 控件，不放赛事源照片卡片或管理按钮。

球搭子查看页只展示目标用户开放给 accepted Connection 的短时水印预览，不提供高清、Storage path 或任何管理动作。以上状态都必须在简体中文 / English 的 375 / 390 / 430px 下验证长赛事名、长说明、图片卡片和 CTA 换行，不得让主要或危险操作被挤出可视区域。

## 11. 空状态
不能只是“暂无数据”。使用轻量网球几何元素 + 人话标题 + 真实解释 + 符合页面职责的下一步动作。

## 12. Loading / Error / Empty / Success
已有缓存时优先保留内容并后台更新。错误提示必须是用户语言。

## 13. 明确禁止
- 电竞化、企业后台化、儿童运动 App 化、专业赛事系统照搬；
- 无业务意义的 AI 默认渐变/玻璃拟态；
- 为入口方便复制同一主功能到多个一级页面；
- 为视觉完整伪造城市、级别、战绩或关系状态；
- 公开/私有赛事只靠一个文字标签区分；
- 把私有赛事做成不可点击的禁用卡或危险警告卡；
- 用 CSS blur 的高清原图冒充安全预览，或把受保护赛事照片作为公开 URL 直接嵌入页面。

## 14. 前端实现约束
新增或明显重构页面前必须阅读三份 baseline、复用相近页面、明确唯一 Primary Action、确认整卡点击语义、检查空状态、删除被替代死代码。赛事卡重构必须同时检查公开卡与私有卡，不允许只验其中一种。照片 UI 重构必须同时验证赛事多图、无权限、默认水印预览、显式高清授权、organizer 源照片上传/删除、participant 主动导入/移出、个人相册 private/partners、partner preview 与中英文窄屏状态。大改部署前做原则偏移审计。
