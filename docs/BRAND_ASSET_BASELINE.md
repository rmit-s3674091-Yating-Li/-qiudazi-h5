# 球搭子品牌资产基线

本文件是「球搭子」Logo、品牌图标与社交分享封面的专项 canonical source。任何 AI 出图、H5 页面、favicon/App icon、Open Graph/微信分享图不得自行创造新的 Logo 或把装饰性图形升级为 Logo。

## 1. 唯一 Logo 原则

- **2026-09-02 产品再次确认：当前 H5 页面左上角圆角鼠尾草绿色方块中的白色 C 形开放圆环/球轨迹标记，是球搭子唯一 canonical 图形 Logo。**实现对应 `.brand-mark` 的 C 形几何语言及 `public/brand-icon.svg`。
- C 标记的核心识别：圆角方形 sage 底色 + 白色开放 C 形圆环/球轨迹；不得替换为双人、双圆点、双球拍、网球或 AI 自创人物符号。
- `public/brand-icon.svg`、favicon/App icon、Share Cover、宣传图、AI 生成图必须以该 C 标记为图形来源；页面 CSS `.brand-mark` 与静态资产应保持同一识别结构。
- Share Cover 中的双人、双圆点、双球拍、网球、瓶子等只能作为场景/装饰元素，不构成 Logo。
- 若未来确需更换 Logo，必须作为独立品牌决策处理，并一次性同步 H5、favicon/App icon、Share Cover、文档和测试；不得通过局部页面或分享图隐式换标。

## 2. Share Cover 定版方向

当前批准的社交分享封面方向：
- 暖奶油色 / 低饱和生活方式视觉为主体，避免大面积荧光黄绿和过强运动广告感；
- 两支球拍作为核心主体，大小/视觉权重基本一致，用“双球拍”自然表达“搭子”概念；
- 可使用两瓶水、两条毛巾、2–3 颗网球等弱化的双人痕迹，表达“虽然不直接出现多人，但处处有两个人一起打球的影子”；
- 不要求直接出现人物；
- 网球黄绿只做焦点色，深网球绿用于品牌文字/线条；
- 保持暖阳、树影、奶油色球场的松弛轻社交气质；
- Share Cover 左上品牌区必须使用 canonical C 标记；场景物品如毛巾/水瓶若出现品牌符号，也只能使用同一 C 标记或完全不放 Logo，禁止 AI 生成替代 Logo。

## 3. 微信/链接分享适配

- 分享缩略图必须针对小尺寸预览单独适配，不得简单把复杂横版宣传图硬裁成小方图。
- 主要识别元素应在安全裁切区内：canonical C Logo / “球搭子”品牌识别 + 双球拍主体 + 少量网球视觉。
- 页面分享标题统一使用当前产品标题“球搭子 · 一起打好每一场球”，除非 PRODUCT/品牌决策正式变更。
- 封面不必重复堆叠过多功能 icon 或小字；微信小缩略图优先保证品牌与网球场景识别。
- Open Graph / social preview 应使用同一批准 Share Cover 资产族，避免微信、普通链接和其他社交预览各自生成不同品牌图。
- SVG 可作为实现中间资产，但微信实际抓取兼容性必须通过 Candidate 真机/真实分享验证；若 SVG 抓取不可靠，应输出 PNG/JPEG 静态 Share Cover，不得仅凭代码配置判定 PASS。

## 4. 禁止事项

- 禁止 AI 在生成 Share Cover 时自行设计并替换 Logo。
- 禁止把双人图标、双圆点、双球拍等装饰符号称为正式 Logo。
- 禁止出现与 C 标记不一致但又放在品牌名称旁、足以让用户误认为 Logo 的符号。
- 禁止使用灰色链条/通用链接占位图作为正式分享视觉；若外部平台因抓取失败显示兜底图，应作为分享兼容性问题调查。
- 禁止为了适配分享图改变产品主 Logo 的比例、结构或核心识别元素。

## 5. 验收

1. H5 页面左上 `.brand-mark`、`public/brand-icon.svg`、favicon/App icon、分享封面中的 Logo 均为同一 C 形标记，不存在第二套品牌 Logo。
2. 微信分享卡片能显示批准的品牌封面，而非灰色通用链条兜底；若平台缓存或格式限制导致失败，应能明确区分资产问题、抓取问题和缓存问题。
3. 小尺寸分享预览中仍能辨识“C 标记 + 球搭子 + 网球 + 双球拍/双人痕迹”的核心概念。
4. Share Cover 色调保持暖奶油/低饱和，不回退到大面积高亮荧光绿。
5. 自动化/人工 Visual QA 发现 Logo 漂移时必须按一致性问题处理，不能把新生成图默认视为新规范。
