# 球搭子｜赛事对阵与轮次展示基线

> 状态：Canonical product / interaction baseline。本文统一规定标准赛事与快速赛事、单打与双打的对阵展示和轮次话术。实现、测试、PRD/PRODUCT/INTERACTION/P0 摘要若与本文冲突，以本文为准并应在当前整改周期内清理冲突。

## 1. 统一原则

- 轮次名称由**赛制与签表结构**决定，不由 `event_mode=standard|quick` 决定。
- 单打和双打共用同一套轮次词汇；区别只在 Entry 是一名球员还是一支双打队。
- 不得为了 Quick Start、双打、人数较少等场景另外发明互相冲突的比赛阶段体系。
- UI 话术应符合普通网球用户直觉，不能仅因为内部淘汰树只有最后一个节点，就制造“前面似乎已经打过预赛/半决赛”的误解。

## 2. 淘汰赛轮次名称

### 2.1 只有两个 Entry、全赛事仅一场淘汰赛

显示：**单场对决**（English: `Single match`）。

不显示“决赛 / Final”。虽然从淘汰树数学结构上该唯一节点也是最终节点，但用户没有经历任何前序轮次，直接称“决赛”容易误导为此前已经存在预赛、1/4 决赛或半决赛。

该规则同时适用于：
- 两名单打球员；
- 两支双打队；
- 标准赛事；
- 快速赛事。

### 2.2 正常多轮淘汰签表

按网球常见轮次统一表达：
- 2 场同轮比赛：半决赛 / Semifinals；
- 4 场同轮比赛：1/4 决赛 / Quarterfinals；
- 8 场同轮比赛：1/8 决赛 / Round of 16；
- 16 场同轮比赛：1/16 决赛 / Round of 32；
- 最后一场：决赛 / Final；
- 更大或无法可靠映射的早期轮次，可使用“第 N 轮 / Round N”。

轮空属于签表结构，不单独改变整轮名称。

## 3. 循环赛与小组赛

循环赛没有“半决赛/决赛”语义，统一按：
- 第 1 轮 / Round 1；
- 第 2 轮 / Round 2；
- ……

小组循环 + 淘汰赛：小组阶段使用轮次/小组语义；进入淘汰阶段后切换到本文第 2 节的淘汰赛轮次体系。

## 4. Match 卡的 PK 关系

Match 卡必须一眼表达“Entry A 对 Entry B”，而不是把两行名字堆叠后在角落放一个 VS。

### 单打

视觉结构应等价于：

`球员 A   VS   球员 B`

### 双打

视觉结构应等价于：

`球员 A / 球员 B   VS   球员 C / 球员 D`

在窄屏可改为纵向，但 `VS` 必须处在两支 Entry 之间，且两队成员保持清晰分组。不得让用户误解成四名独立选手或看不出队友关系。

比分存在时仍保持 Entry A / VS / Entry B 的主结构，比分作为各 Entry 的附属信息展示。

## 5. 单场赛事的信息层级

当整个淘汰赛只有一场比赛时：
- 对阵区域标题可使用“对阵 / Matchup”；
- 轮次标题使用“单场对决 / Single match”；
- 点击比赛卡进入比赛详情/记分；
- 不应为了模拟多轮签表而显示“左右滑动查看各轮”等无意义提示；
- 当前页面已经完整展示唯一对阵时，不应再重复提供一个没有新增信息价值的巨大“查看对阵”主按钮。

## 6. 状态与轮次严格分离

“未开始 / 进行中 / 已结束”是 Match 状态；“单场对决 / 半决赛 / 决赛”等是轮次名称。两类文案不能互相替代。

Event 的 `locked / ongoing / finished` 也不能用于推导淘汰轮次名称。轮次只根据权威 Match / bracket 结构显示。

## 7. 验收要求

至少验证：
1. 2 个 singles Entry 的 knockout 显示“单场对决”，不显示“决赛”；
2. 2 个 doubles Entry 同样显示“单场对决”；
3. 双打 Match 卡明确显示 Team A — VS — Team B；
4. 4 Entry 淘汰赛显示“半决赛 → 决赛”；
5. 8 Entry 淘汰赛显示“1/4 决赛 → 半决赛 → 决赛”；
6. round-robin 继续显示“第 N 轮”，不套用淘汰赛术语；
7. standard / quick 使用同一轮次函数；
8. 中文与 English 语义一致；
9. 375 / 390 / 430px 下队伍名、VS、比分不溢出或错组。
