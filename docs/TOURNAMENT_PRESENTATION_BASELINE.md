# 球搭子｜赛事对阵、计分与轮次展示基线

> 状态：Canonical product / interaction baseline。本文统一规定标准赛事与快速赛事的对阵、网球计分层级、轮次、单场结果和完赛展示。

## 1. 网球计分层级

统一按国际网球通用层级表达：**分（point）→ 局（game）→ 盘（set）→ 比赛（match）→ 赛事（event）**。产品文案不得混用。

- `games_6` 表示“每盘先到 6 局”的传统盘规则，不表示 6 盘、6 轮或 6 场比赛。
- `best_of=1` 表示 1 盘制；一盘产生胜者后 Match 即结束。
- `best_of=3` 表示 3 盘 2 胜；`best_of=5` 表示 5 盘 3 胜。
- 传统 6 局盘在 6:6 进入抢七时，UI 应明确“6:6 抢七”；抢七小分与盘内局分分开记录。
- UI 推荐组合表达：`1盘制 · 每盘先到6局 · 6:6抢七`，不得只写含混的“6局制 · 局制1”。

## 2. 轮次名称

轮次名称由赛制与签表结构决定，不由 `event_mode` 决定。单打和双打共用同一套轮次词汇。

### 2.1 两个 Entry、全赛事仅一场淘汰赛

显示 **单场对决 / Single match**，不显示“决赛 / Final”。该规则适用于 singles/doubles、standard/quick。

### 2.2 正常多轮淘汰签表

- 2 场同轮：半决赛；
- 4 场同轮：1/4 决赛；
- 8 场同轮：1/8 决赛；
- 16 场同轮：1/16 决赛；
- 多轮淘汰签表最后一场：决赛；
- 无法可靠映射时：第 N 轮。

循环赛按第 N 轮；小组+淘汰赛分别使用小组轮次和淘汰轮次。

## 3. Match 卡

Match 卡必须明确 `Entry A — VS — Entry B`。双打必须保持队友分组：`A/B — VS — C/D`。比分存在时显示每盘局分，不能把“盘分”和“局分”混为一个数字。

## 4. 录入比分

比赛详情主入口使用 **“录入比分 / Record score”**，不使用“直接录入最终比分”作为默认动作。

产品提供两种模式：
1. **录入比分**：按盘填写已完成的盘比分；1盘制只有一盘，3盘2胜最多三盘，达到胜盘数后整场 Match 结束。
2. **逐分实时记分**：按 point 逐分记录，由计分引擎自动累计 game / set / match。

“每盘先到6局”不是允许录入六个“第N盘”。对于 1盘制 6局盘，合法的 `6:3` 等结果会直接结束唯一一盘和该 Match。

比赛已经结束后，入口改为“更正比分”。更正确认文案必须按实际影响分层：
- 没有后续对阵变化：仅提示“替换本场已记录赛果并重新计算本场结果”；
- 会改变尚未开始的后续淘汰对阵：明确列出会重建的后续比赛数量；
- 不得向单场 Quick Event 展示“不改变其他比赛参赛者”这类无关工程话术。

### 4.1 实时记分版本同步

逐分实时记分是高频连续写入场景。每一次 `point / undo / begin / score` 命令成功后，客户端必须**立即采用服务端返回的最新 Snapshot 作为当前权威状态**，包括最新 `event.version`、`match.version`、point logs、set scores 和 Match/Event 状态；不得丢弃命令返回值后继续使用旧版本。

同一设备正常连续点击 `+1分` 不得因为客户端自身版本滞后触发 `VERSION_CONFLICT`。只有确有另一页面/另一设备在同一版本窗口内先完成写入时，才属于真实并发冲突；此时应刷新到最新赛况后让用户继续，而不是把普通连续记分当作异常。

命令成功后还应失效相关赛事列表/详情缓存，避免用户返回 Hall、赛事详情或我的赛事时看到旧状态。

### 4.2 逐分裁判记分的网球语义与 UI

逐分实时记分必须展示**网球比分本身**，不得把内部 point counter 直接暴露给用户。

- 普通局当前分使用 `0 / 15 / 30 / 40 / AD`；40:40 显示 Deuce / 平分；优势方显示 AD。不得显示 `3:4`、`5:3` 这类内部原始计数。
- 抢七局才显示连续数字小分，例如 `5:3`、`7:5`；界面必须明确当前处于“抢七”，避免与普通局混淆。
- 页面主信息层级固定为：**参赛双方 → 当前盘局分 → 当前局分 → 得分操作**。盘数/胜盘数属于辅助信息，不应抢占主视觉。
- Live 模式每次点击“某方得分”只写入一个 point log；局分、盘分、Match 结果全部由计分引擎派生，用户不手工维护。
- Live 模式不得提供“删除上一局”或对已记局进行 `+/-` 手工编辑。正常纠错动作只有“撤销上一分”；如需改写已完成赛果，退出 Live 模式后走受保护的“更正比分”流程。
- 每一分保存成功后界面立即更新。达到 game/set/match 胜负条件时自动推进，不再要求用户额外点击“确认结果”才能让比赛成立。
- 得分按钮应直接以双方姓名/队名表达，例如“张三 得分 / 李四 得分”，而不是只显示抽象的 `+1`；双打保持整队名称。
- 历史记录可以展示“得分记录/已完成盘分”，但默认只读；不得把派生出来的局结果做成可随手增减的第二套真源。

## 5. Match 完成与 Event 完成

Match `finished` 和 Event `finished` 是不同层级，所有页面必须使用同一权威 Event 状态。

Quick Event 若全赛事只有一个真实 Match，则该 Match 完成时自动完成 Event：
- Event → `finished`；
- 写入 `finished_at`；
- Hall 同步显示已结束；
- 排名/结果区显示最终赛果；
- organizer 赛事相册上传立即开放。

多场赛事继续要求所有比赛完成后由赛事收口规则进入 Event finished；不得仅凭某一场 Match finished 把整个 Event 宣告结束。

## 6. 单场结果展示

只有两个 Entry、唯一一场比赛的 Quick/standard knockout 不使用“冠军 / 亚军 / 领奖台”包装。完赛后展示：
- 本场胜方 / Match winner；
- 另一方 / Other side；
- 实际盘比分/局比分。

只有真实多轮淘汰赛事才使用冠军、亚军、并列季军等赛事名次语义。

## 7. 状态一致性

以下页面必须以同一 Event 状态保持一致：赛事大厅、赛事详情、排名/结果、赛事相册、我的赛事。禁止出现“排名已经宣告冠军 + 相册仍不可上传 + Hall 仍显示进行中”的分裂状态。

## 8. 验收

至少验证：
1. 2 Entry knockout 显示“单场对决”，不显示“决赛”；
2. `best_of=1 + games_6` 显示“1盘制 · 每盘先到6局”，用户不会理解成6盘/6轮；
3. 6:3 合法结束一盘制 Match；
4. 3盘2胜最多按三盘记录并在任一方取得2盘后结束；
5. 比赛详情默认入口为“录入比分”，并保留逐分实时记分；
6. 单场比分更正不显示无关的“其他比赛参赛者”提示；
7. 逐分实时记分可连续完成 15→30→40→Game，不因同端自身版本滞后出现 VERSION_CONFLICT；
8. 每次 point/undo 成功后 UI 立即采用 command 返回的最新 event.version + match.version；
9. 真实双设备并发仍能被版本控制拦截并刷新到最新赛况；
10. 普通局从 Love/0、15、30、40、Deuce、AD 到 Game 的用户显示正确，绝不显示内部 `3:4` / `5:3` point counter；
11. 抢七时才显示连续数字小分，并明确“抢七”；
12. Live 模式仅“某方得分 + 撤销上一分”，无“删除上一局”、无已记局 `+/-`、无额外“确认结果”作为比赛成立条件；
13. 单场 Quick Match 完成后 Event 自动 finished；
14. Event finished 后 Hall、详情、结果、相册状态一致；
15. 单场结果显示“本场胜方/另一方”，不显示冠亚军；
16. 多轮淘汰赛仍正常显示半决赛/决赛和最终赛事名次；
17. 中文与 English 语义一致；
18. 375 / 390 / 430px 不溢出或错组。
