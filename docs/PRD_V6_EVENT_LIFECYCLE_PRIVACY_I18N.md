# 球搭子 H5 MVP｜PRD V6 增量基线

> 日期：2026-08-29。此文档承接 PRD V5，并记录本次大版本已确认的新产品规则。与旧文档冲突时，以本文件 + 当前 PRODUCT_BASELINE + `docs/PHOTO_ALBUM_BASELINE.md` 为准。

## 1. 参赛建议级别
赛事不再使用单一“赛事级别”作为用户侧概念，改为“参赛建议级别”区间。六档仍为：2.0及以下 / 2.5 / 3.0 / 3.5 / 4.0 / 4.5及以上。创建/编辑可设置最低、最高，允许单边开放或不限；最低不得高于最高。它是发现/匹配信息，不是硬报名资格。公开赛事卡、完整详情、邀请信息展示；私有赛事脱敏预览也允许展示。旧单值 level 迁移：≤2.0→仅最高，≥4.5→仅最低，中间档→min=max。

## 2. 比赛时间与最晚报名时间
比赛日期和开赛时间进入创建赛事 P0 必填。最晚报名时间默认自动取“开赛前2小时”，组织者可以设置得更早，但不能晚于开赛前2小时。修改开赛时间后，若原截止时间超出新边界，自动收紧到新的合法最晚值并提示。

## 3. 报名截止、名单锁定与首次编排
截止时间是服务端权限边界，不是前端提示。到达截止点后，所有会改变参赛名单的普通路径必须拒绝：单打/双打报名、组织者代临时球搭子报名、双打最终 Entry 提交、普通邀请接受、双打邀请接受、普通退赛。旧页面、分享深链和直接 RPC 调用不得绕过。组织者可在截止前提前锁定。截止后进入“报名截止/名单锁定”阶段，不等于比赛已经开始。

标准赛事正常生命周期固定为：**创建 → 报名/组队/候补 → 锁定名单 → 自动生成首次对阵 → 查看/复核对阵 → 开始赛事 → 记分**。组织者确认锁定时，系统先执行权威 roster lock，再立即自动调用现有 tournament draw engine。正常成功路径不得要求用户额外点击一次“生成对阵”。若 lock 已成功而首次 draw 因网络或 Edge Function 临时失败，赛事保持真实 locked 状态，页面必须明确提供“继续生成对阵 / Retry draw”；该恢复动作只对当前 locked event 重试 draw，不重复 lock、不改变 roster，也不创建新赛事。

首次对阵生成后，组织者主要动作是“查看对阵 / 开始赛事”；“重新生成对阵”和“解锁名单”为次级受保护动作。开赛前人员临时变化按“解锁 → 清空签表 → 调整名单/候补 → 重新锁定 → 自动生成首次对阵”处理；一旦已有真实比赛开始或结束，禁止解锁或无保护重建签表。

数据库通过 registration_deadline + event_registration_open() 做精确写入校验；共享测试环境使用 pg_cron 每5分钟把已过期且仍为 signup 的赛事物理状态同步为 locked。即使 cron 尚未执行，服务端写入校验和列表有效状态也必须立即按截止时间视为已锁定。cron 导致的物理 locked 不等于自动发起 draw；组织者进入管理页后必须得到清晰的 locked/no-draw 恢复入口，不得被误认为已经完成编排。

## 4. 赛事卡报名截止提示
公开/完整赛事卡显示安静的截止提示，不做秒级/分钟级跳动，也不因倒计时增加 Supabase 请求：>24小时显示具体截止日期时间；1–24小时显示“距报名截止约 N 小时”；不足1小时显示“报名即将截止”；截止后显示“报名已截止/报名已结束”。仅使用已加载 deadline + 本地时钟计算。最终可报名性始终以服务器时间为准。

私有赛事大厅脱敏卡不展示报名截止、比赛时间或任何可用于反推活动时间的信息；获得详情权限后才显示。

## 5. 设置与隐私
“我的 → 设置与隐私”成为真实设置页。个人档案字段按字段控制球搭子浏览可见性，当前字段：头像、水平级别、常打城市、约球时间、单双打偏好。昵称及赛事共同事实不受此开关影响。隐私设置不得改写/隐藏赛事名单、比分、赛果等赛事规则要求公开给合法赛事参与者的共同事实。

邀请隐私分为两个独立开关，默认开启：允许球搭子发送赛事邀请；允许球搭子发送双打组队邀请。必须由后端邀请 RPC 执行，不允许只隐藏前端按钮。

### 5.1 赛事相册与参与赛事相册
赛事照片属于受限用户内容，与赛事本身的公开/私有可见范围分离。即使赛事为公开赛事，赛事页面照片也只允许赛事组织者与该赛事有效 Entry 中的真实参赛用户查看；普通浏览者、仅知道赛事 URL/ID 的用户、仅收到邀请但尚未形成有效 Entry 的用户均不得获得赛事照片读取权限。

**赛事相册是照片源。** 一场赛事允许存在多张赛事照片；上传与源相册管理权只属于赛事创建人/组织者。其他参赛者即使有查看权，也不能上传、替换或删除赛事源照片。

MVP 不同时给组织者提供“从赛事相册移除”和“永久删除”两个近义动作。组织者在赛事页统一使用 **“删除照片”**。删除前必须二次确认，明确：照片将从本场赛事相册永久删除，其他参赛者之后不能再从该赛事获取这张照片；**此前已经成功加入参赛者“参与赛事相册”的个人照片不受影响。** 删除必须由服务端重新校验 organizer 权限并一致处理赛事源 metadata、源高清原图和源水印预览，不得允许客户端通过任意 Storage path 删除他人对象。

**系统不得自动把赛事照片导入参赛者个人相册。** 实际参赛者只能从自己参加赛事的当前赛事相册中逐张主动选择“加入我的参与赛事相册”。该动作不是简单收藏引用：服务端在导入瞬间确认 actual participant 身份和源照片仍有效，并形成属于该用户自己的受保护个人相册资产/快照。导入成功后，其生命周期独立于赛事源照片。

因此，组织者后续删除赛事源照片时，只影响赛事页面和未来新的导入请求；已经导入成功的 participant personal album item 继续存在。个人资产若保留 source_event_photo_id 仅用于追溯，源删除时必须 SET NULL 或等价解耦，禁止级联删除个人资产。参赛者可以在自己的“参与赛事相册”中执行“移出我的相册”，该动作只删除本人的个人相册资产，不影响赛事源照片或其他参赛者。

“我的”页面提供独立入口 **“参与赛事相册”**，展示本人主动加入成功的照片并按赛事分组。

“我的 → 设置与隐私”**不承担赛事照片上传、编辑或删除**，只提供个人级别的 **“参与赛事相册可见范围”**：默认“仅自己可见”，可切换为“搭子可见”。该设置作用于整个人的参与赛事相册，MVP 不要求每张照片再单独配置可见性。

只有 accepted Connection 可以查看目标用户主动设为“搭子可见”的参与赛事相册。搭子侧只展示个人副本的受保护水印预览；列表接口不得下发 Storage object path，预览必须由服务端重新校验 Connection 与目标用户相册 visibility 后签发短时 URL；搭子不获得高清原图访问能力，也不获得赛事照片管理权或目标用户个人相册修改权。

赛事页面默认不得直接暴露高清原图。组织者与 actual participant 明确点击“小眼睛 / 查看高清”后，服务端重新校验赛事角色并签发短时高清访问能力。照片存储保持 private；默认使用真实派生水印预览，不以 CSS 模糊高清原图替代安全边界。

详细照片产品和权限规则以 `docs/PHOTO_ALBUM_BASELINE.md` 为准。

### 5.2 快速开赛
“快速开赛”是标准赛事之外的动作入口，解决“球友已经在微信群/线下约好，不需要先在球搭子招募报名，但希望使用编排、记分、排名、战绩和照片”的场景。

底部现有四个主导航保持原样；导航中央增加向上凸起的圆形“快速开赛”按钮。它是全局动作，不是第五个长期页面导航，不改变“战绩”等既有能力在“我的”中的归属。

快速开赛流程：
1. 选择单打 / 双打；
2. 从自己的 Player 资产中选择参赛者，支持现场新增临时 Player；单打至少 2 人，双打至少 4 人且为偶数，MVP 按选择顺序每两人组成一队；
3. 设置城市、可选场地、单循环/单淘汰和计分规则；
4. 点击“确认并生成对阵”，服务端原子创建 Event / Entry / EntryPlayer，`event_mode='quick'`，名单直接 locked，随后自动生成首次对阵并进入赛事管理。

quick event 不走公开招募、报名截止、候补、普通赛事邀请、双打组队邀请，**也不进入普通赛事大厅发现流**。它只在创建人和实际参赛者自己的赛事上下文中出现；即使内部使用 `visibility='private'`，也不得复用标准私有赛事的脱敏大厅卡。不得为了复用标准赛事而伪造未来时间或 deadline。比赛日期/开赛时间可直接取创建时本地赛事时间，`registration_deadline` 对 quick event 为 null。

`event_mode` 是明确业务字段，必须从 DB schema / migration 贯穿到 `list_events`、`get_event_snapshot`、TypeScript `Event` 与页面判断；不得通过 deadline 是否为空、status 或赛事名称反推 quick/standard。

如果 Event / Entry 已创建成功，但首次 draw 因网络或 Edge Function 临时失败，客户端必须持久保存该 event id/version 并进入“赛事已创建 / 继续生成对阵”的恢复状态。恢复操作只能对该已存在赛事重试 draw，**不得再次调用 `create_quick_event` 产生重复赛事**；刷新快速开赛页面后仍应恢复 pending event。用户可进入已创建赛事管理页查看，但在 pending draw 被处理前不得无提示创建第二场 quick event。

快速开赛只是创建方式不同；创建后继续使用标准 Event / Entry / Match、viewer_role、记分、排名、完赛、战绩和照片权限模型。开赛前如果有人临时不来，组织者通过赛事管理调整名单并重新生成对阵；赛事真正开始后不允许普通替换 Player。

## 6. 语言
H5 MVP 支持简体中文 / English。语言偏好本地持久化，不引入复杂国际化后端。建立统一轻量 i18n 层；新增核心用户可见文案原则上进入语言资源，不再继续无序硬编码。进入正式英文可用验收前，赛事大厅、我的赛事、赛事详情、创建/编辑、报名/邀请、球搭子、我的、设置与隐私以及核心状态/错误/空状态必须完成全量英文覆盖；不得出现影响任务理解的半翻译页面。业务逻辑不得通过比较中英文展示文案判断报名状态、权限或赛事状态。

快速开赛三步流程和中央入口同样必须提供完整中英文文案，并在 375 / 390 / 430px 检查按钮、玩家列表、双打组队提示和底部 safe-area。

## 7. 私有赛事边界保持
本次新增 suggested level range 可进入私有脱敏预览；registration_deadline 不进入。稳定原则继续为：大厅可发现 ≠ 获得赛事详情权限 ≠ 获得报名资格。赛事照片另按 5.1 的受限内容规则授权，公开赛事详情可见不等于照片可见。

quick event 不是招募型大厅赛事，**既不以 public 招募卡，也不以 private 脱敏卡出现在普通赛事大厅**；是否未来允许分享 quick event 只影响赛事详情分享，不得把它变成可报名赛事。

## 8. 权威身份与“我参与的”语义
赛事详情中的组织者/受邀者/参与者身份必须以服务端赛事快照返回的 `viewer_role` 等权威权限事实为准；本地 Profile/cache 只能辅助展示，不能单独决定组织者管理入口。旧 auth session 映射到 canonical Profile 的恢复场景下，合法组织者仍必须获得正确管理能力。比赛详情、实时记分和直接录入比分页同样属于身份敏感页面，是否允许组织者记分/更正比分必须沿用同一权威 `viewer_role`，不得退回本地 Profile ID 比较；本地比分级联预演需要 actor 时应使用快照中的 canonical 赛事 owner 身份。

“我的赛事 → 我参与的”按实际有效 Entry 中的 Player 参与事实判断，而不是仅按谁发起报名判断。单打本人以及双打 Entry 中两名已关联真实用户的搭档，都应看到该赛事；仅接受普通赛事邀请或仅接受双打组队邀请但尚未形成有效 Entry，不应提前出现。服务端私有赛事预览和赛事快照也必须按相同 Entry/Player 参与事实识别 participant；已形成有效 Entry 后 participant 身份优先于历史邀请状态。

quick event 中由组织者选择的临时 Player 仍按 Player 规则积累历史；以后真实用户 claim/关联历史时继续遵守 Player ≠ Profile 和冲突校验。

## 9. P0 回归重点
截止前1秒/截止瞬间/截止后报名；提前打开页面后超时提交；双打搭档已接受但未形成 Entry；组织者代报名；截止后退赛；旧邀请接受；直接 RPC 绕过；私有卡不泄露 deadline；建议级别旧数据迁移；邀请隐私服务端拦截；档案字段服务端裁剪；语言切换持久化与核心流程全英文；业务逻辑不依赖展示文案；旧 auth session/canonical Profile 下组织者管理入口与比赛记分/比分更正能力；双打两名真实搭档均进入“我参与的”且在私有赛事快照中识别为 participant；标准赛事锁定后自动首次 draw、draw 临时失败恢复、开赛前解锁调整重锁、开赛后禁止重建签表；赛事照片仅 organizer/actual participant 可读、一场多图、只有 organizer 可上传/删除赛事源照片、participant 逐张主动导入/移出“参与赛事相册”、系统不自动导入、organizer 删除源照片后未来不可再导入但已导入个人资产继续存在、隐私设置只控制个人参与赛事相册“仅自己/搭子可见”、搭子只获得短时水印预览且不获得高清/Storage path；390px及更窄表单、卡片、英文长文本和照片操作布局。

快速开赛属于当前新增 P1 能力，不反向改变上述 P0 标准赛事规则；一旦进入受控 Preview，需独立验证 quick event 创建原子性、`event_mode` 全链路、普通大厅不可发现、Player 去重/归属、自动生成对阵、draw 失败恢复不重复建赛、375/390/430 中央按钮不遮挡四个既有导航，以及 quick event 不开放普通报名/候补。
