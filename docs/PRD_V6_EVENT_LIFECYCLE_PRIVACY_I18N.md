# 球搭子 H5 MVP｜PRD V6 增量基线

> 日期：2026-08-29。此文档承接 PRD V5，并记录本次大版本已确认的新产品规则。与旧文档冲突时，以本文件 + 当前 PRODUCT_BASELINE + `docs/PHOTO_ALBUM_BASELINE.md` 为准。

## 1. 参赛建议级别
赛事不再使用单一“赛事级别”作为用户侧概念，改为“参赛建议级别”区间。六档仍为：2.0及以下 / 2.5 / 3.0 / 3.5 / 4.0 / 4.5及以上。创建/编辑可设置最低、最高，允许单边开放或不限；最低不得高于最高。它是发现/匹配信息，不是硬报名资格。公开赛事卡、完整详情、邀请信息展示；私有赛事脱敏预览也允许展示。旧单值 level 迁移：≤2.0→仅最高，≥4.5→仅最低，中间档→min=max。

## 2. 比赛时间与最晚报名时间
比赛日期和开赛时间进入创建赛事 P0 必填。最晚报名时间默认自动取“开赛前2小时”，组织者可以设置得更早，但不能晚于开赛前2小时。修改开赛时间后，若原截止时间超出新边界，自动收紧到新的合法最晚值并提示。

## 3. 报名截止与名单锁定
截止时间是服务端权限边界，不是前端提示。到达截止点后，所有会改变参赛名单的普通路径必须拒绝：单打/双打报名、组织者代临时球搭子报名、双打最终 Entry 提交、普通邀请接受、双打邀请接受、普通退赛。旧页面、分享深链和直接 RPC 调用不得绕过。组织者可在截止前提前锁定。截止后进入“报名截止/名单锁定，等待编排或开赛”阶段，不等于比赛已经开始。

数据库通过 registration_deadline + event_registration_open() 做精确写入校验；共享测试环境使用 pg_cron 每5分钟把已过期且仍为 signup 的赛事物理状态同步为 locked。即使 cron 尚未执行，服务端写入校验和列表有效状态也必须立即按截止时间视为已锁定。

## 4. 赛事卡报名截止提示
公开/完整赛事卡显示安静的截止提示，不做秒级/分钟级跳动，也不因倒计时增加 Supabase 请求：>24小时显示具体截止日期时间；1–24小时显示“距报名截止约 N 小时”；不足1小时显示“报名即将截止”；截止后显示“报名已截止/报名已结束”。仅使用已加载 deadline + 本地时钟计算。最终可报名性始终以服务器时间为准。

私有赛事大厅脱敏卡不展示报名截止、比赛时间或任何可用于反推活动时间的信息；获得详情权限后才显示。

## 5. 设置与隐私
“我的 → 设置与隐私”成为真实设置页。个人档案字段按字段控制球搭子浏览可见性，当前字段：头像、水平级别、常打城市、约球时间、单双打偏好。昵称及赛事共同事实不受此开关影响。隐私设置不得改写/隐藏赛事名单、比分、赛果等赛事规则要求公开给合法赛事参与者的共同事实。

邀请隐私分为两个独立开关，默认开启：允许球搭子发送赛事邀请；允许球搭子发送双打组队邀请。必须由后端邀请 RPC 执行，不允许只隐藏前端按钮。

### 5.1 赛事相册与参与赛事相册
赛事照片属于受限用户内容，与赛事本身的公开/私有可见范围分离。即使赛事为公开赛事，赛事页面照片也只允许赛事组织者与该赛事有效 Entry 中的真实参赛用户查看；普通浏览者、仅知道赛事 URL/ID 的用户、仅收到邀请但尚未形成有效 Entry 的用户均不得获得赛事照片读取权限。

**赛事相册是照片源。** 一场赛事允许存在多张赛事照片；上传与源相册管理权只属于赛事创建人/组织者。其他参赛者即使有查看权，也不能上传、替换或删除赛事源照片。

MVP 不同时给组织者提供“从赛事相册移除”和“永久删除”两个近义动作。组织者在赛事页统一使用 **“删除照片”**。删除前必须二次确认，明确：照片将从本场赛事相册永久删除；已经被参赛者加入“参与赛事相册”的对应引用也将同步失效；操作不可恢复。删除必须由服务端重新校验 organizer 权限并一致处理源 metadata、个人收藏引用、高清原图和水印预览，不得允许客户端通过任意 Storage path 删除他人对象。

**系统不得自动把赛事照片导入参赛者个人相册。** 实际参赛者只能从自己参加赛事的当前赛事相册中逐张主动选择“加入我的参与赛事相册”；已加入后可以“移出我的参与赛事相册 / 取消收藏”。该操作只改变本人的收藏引用，不修改赛事源照片，也不影响其他人。

“我的”页面提供独立入口 **“参与赛事相册”**，展示本人主动选择加入的赛事照片并按赛事分组。个人相册保存的是对仍有效赛事源照片的受控引用，不复制出一份脱离赛事源生命周期的永久副本；因此组织者后来删除源照片时，所有对应个人引用同步消失。

“我的 → 设置与隐私”**不承担赛事照片上传、编辑或删除**，只提供个人级别的 **“参与赛事相册可见范围”**：默认“仅自己可见”，可切换为“搭子可见”。该设置作用于整个人的参与赛事相册，MVP 不要求每张照片再单独配置可见性。

只有 accepted Connection 可以查看目标用户主动设为“搭子可见”的参与赛事相册。搭子侧只展示受保护水印预览；列表接口不得下发 Storage object path，预览必须由服务端重新校验 Connection、目标用户相册 visibility、源照片仍有效后签发短时 URL；搭子不获得高清原图访问能力，也不获得赛事照片管理权或目标用户收藏修改权。

赛事页面默认不得直接暴露高清原图。组织者与 actual participant 明确点击“小眼睛 / 查看高清”后，服务端重新校验赛事角色并签发短时高清访问能力。照片存储保持 private；默认使用真实派生水印预览，不以 CSS 模糊高清原图替代安全边界。

详细照片产品和权限规则以 `docs/PHOTO_ALBUM_BASELINE.md` 为准。

## 6. 语言
H5 MVP 支持简体中文 / English。语言偏好本地持久化，不引入复杂国际化后端。建立统一轻量 i18n 层；新增核心用户可见文案原则上进入语言资源，不再继续无序硬编码。进入正式英文可用验收前，赛事大厅、我的赛事、赛事详情、创建/编辑、报名/邀请、球搭子、我的、设置与隐私以及核心状态/错误/空状态必须完成全量英文覆盖；不得出现影响任务理解的半翻译页面。业务逻辑不得通过比较中英文展示文案判断报名状态、权限或赛事状态。

## 7. 私有赛事边界保持
本次新增 suggested level range 可进入私有脱敏预览；registration_deadline 不进入。稳定原则继续为：大厅可发现 ≠ 获得赛事详情权限 ≠ 获得报名资格。赛事照片另按 5.1 的受限内容规则授权，公开赛事详情可见不等于照片可见。

## 8. 权威身份与“我参与的”语义
赛事详情中的组织者/受邀者/参与者身份必须以服务端赛事快照返回的 `viewer_role` 等权威权限事实为准；本地 Profile/cache 只能辅助展示，不能单独决定组织者管理入口。旧 auth session 映射到 canonical Profile 的恢复场景下，合法组织者仍必须获得正确管理能力。比赛详情、实时记分和直接录入比分页同样属于身份敏感页面，是否允许组织者记分/更正比分必须沿用同一权威 `viewer_role`，不得退回本地 Profile ID 比较；本地比分级联预演需要 actor 时应使用快照中的 canonical 赛事 owner 身份。

“我的赛事 → 我参与的”按实际有效 Entry 中的 Player 参与事实判断，而不是仅按谁发起报名判断。单打本人以及双打 Entry 中两名已关联真实用户的搭档，都应看到该赛事；仅接受普通赛事邀请或仅接受双打组队邀请但尚未形成有效 Entry，不应提前出现。服务端私有赛事预览和赛事快照也必须按相同 Entry/Player 参与事实识别 participant；已形成有效 Entry 后 participant 身份优先于历史邀请状态。

## 9. P0 回归重点
截止前1秒/截止瞬间/截止后报名；提前打开页面后超时提交；双打搭档已接受但未形成 Entry；组织者代报名；截止后退赛；旧邀请接受；直接 RPC 绕过；私有卡不泄露 deadline；建议级别旧数据迁移；邀请隐私服务端拦截；档案字段服务端裁剪；语言切换持久化与核心流程全英文；业务逻辑不依赖展示文案；旧 auth session/canonical Profile 下组织者管理入口与比赛记分/比分更正能力；双打两名真实搭档均进入“我参与的”且在私有赛事快照中识别为 participant；赛事照片仅 organizer/actual participant 可读、一场多图、只有 organizer 可上传/删除源照片、participant 逐张主动加入/移出“参与赛事相册”、系统不自动导入、organizer 删除源照片后个人引用同步失效、隐私设置只控制个人参与赛事相册“仅自己/搭子可见”、搭子只获得短时水印预览且不获得高清/Storage path；390px及更窄表单、卡片、英文长文本和照片操作布局。
