# R-006｜场地不应先做成“地图产品”：先验证“复用地点上下文”

- 日期：2026-10-02
- 状态：DECISION_CANDIDATE
- 研究主题：地图 / 场地 / 发现 / 复约中的地点摩擦
- 原始产品问题：V7 已有静态场地定位能力，但下一版本是否应继续扩展为附近球场搜索/地图发现，仍缺少用户证据。更基础的问题可能是：用户往往已经知道要去哪里打，只是不想每次重新搜索、确认入口/场馆、复制地址和向同伴解释集合点。
- 来源/证据：Uber 官方将 Saved Places 定义为高频目的地捷径，并在复杂场所通过推荐 pickup spot、可移动 pin 和明确 Confirm Pickup 收敛地点决策；Airbnb 将地图与搜索结果联动，并允许把地点保存到行程、与同行者共享，强调地点是具体行程的上下文而非独立地图收藏；Google Maps 的 You 入口提供 Recently saved / Nearby saved，把“最近/附近的已知地点”置于重新搜索之前；Meetup 的发现页则把位置、日期、距离、类别作为事件发现过滤维度。Airbnb 2026 年 9 月更新进一步强化自然语言搜索和筛选，但这类 AI 搜索建立在大规模供给与结构化地点数据之上，不适合作为球搭子当前默认方向。
- 参考产品/行业：Uber（高频地点捷径与精确集合点）、Airbnb（地图 + 行程上下文 + 协作保存）、Google Maps（最近/附近已保存地点）、Meetup（活动发现的位置过滤）。
- Function pattern：① 高频地点优先“最近使用/已保存/从上一场复用”，而非每次从零搜索；② 搜索负责找到地点，确认动作负责锁定本次活动地点，两者分离；③ 在复杂场馆中，“场馆”与“实际集合点/入口”可分层；④ 地点信息跟随具体活动传播，参与者不必重新查询；⑤ 只有在用户确实不知道去哪打时，才进入“发现附近场地”的 marketplace/discovery 问题。
- UI/UX pattern：创建/复约流程中地点字段可优先显示“上一场”“最近使用”“常用地点”短列表，搜索作为次级入口；地图用于确认和纠错，而不是默认占据整个首屏。地点详情应优先显示人能识别和行动的信息（场馆名、简短地址/区域、集合点说明、导航动作），避免经纬度/技术地址噪声。复杂场馆可借鉴 Uber 的“推荐点 → 可调整 → 明确确认”三步，而不是让用户面对无限地图自由度。活动详情中的地点应保持单一事实源，分享/邀请直接携带。
- Why it works：熟人约球和复约是高重复场景，地点往往具有强惯性。把地点从“每次搜索任务”变成“活动上下文的可复用属性”，可同时降低组织者创建成本和参与者理解/问路成本，并与 R-001/R-002 的 Play Again 方向直接连接。
- Applicability：高适用于固定场馆、固定小组、周期局、复制上一场；中等适用于一次性赛事；只有当用户存在明显“我想打但不知道附近哪里能打”的需求时，完整球场发现才有高价值。
- Counterexample / 风险：Uber 的 pickup pin 解决的是米级会合，球搭子未必需要同等精度；Airbnb/Google Maps 拥有庞大 POI 与搜索基础设施，球搭子不应复制其地图复杂度；保存地点若演化成完整场馆数据库，会引入去重、名称、营业状态、设施、价格、预订、审核和数据维护成本。AI 搜索在当前供给规模下也可能是过早复杂化。
- 球搭子可能含义：下一版“地图/场地”候选应拆成两个问题，不再混为一谈：A. 已知地点的复用与集合（高关联 Play Again）；B. 未知地点的发现与比较（独立 marketplace/discovery 假设）。目前建议先验证 A，暂缓把 B 作为 V8 主轴。
- Smallest validation：不开发。拿 5–8 位用户最近 3 次真实约球记录，记录地点来源属于“固定场馆 / 上一次地点 / 群友推荐 / 临时搜索 / 附近发现”哪类；再用两张低保真创建页比较 A=搜索场地，B=上一场 + 最近使用 + 搜索其他地点。另询问到场前是否经常发生“哪个门/哪片场/具体在哪集合”的二次沟通。若多数场次来自固定/复用地点且 B 明显更快，则支持“context reuse”；若大量用户先解决“附近哪里有合适球场”，再升级研究完整发现。
- 建议优先级：高（作为 V8 主轴的范围裁剪问题；外部模式证据中强，球搭子自身证据仍弱）
- 未决问题：常用地点应属于个人、小组还是 Club；是否只需保存 display name + 地址/坐标 + 集合备注；集合点是否需要精确 pin；场地复用是否应成为“复制上一场”的默认继承项。

## 与既有研究的关系

R-006 不替代 R-001/R-002，而是收窄其地点子问题：若 Play Again 成立，优先复用上一场/常用地点；“附近球场发现”保持独立假设，不因已有地图能力而自动进入 V8。未经用户确认，本记录不构成实现任务。
