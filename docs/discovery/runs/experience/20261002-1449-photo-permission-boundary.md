# 赛事照片权限：从我这里移除 ≠ 从赛事里撤回

- 时间：2026-10-02
- 状态：HYPOTHESIS / DECISION_CANDIDATE
- 建议优先级：高

## Original product problem

当前赛事照片操作容易把个人动作与赛事共享源管理混在一起。用户需要清楚知道自己是在“只影响自己”，还是“影响整场赛事所有人”。

## Function pattern

建议权限边界：

- 普通参与者：
  - 查看
  - 分享
  - 保存到设备
  - 如存在 personal state，可“从我这里移除”

- 赛事照片上传者 / 赛事管理员 / 具备相应权限者：
  - 撤回自己上传的赛事照片
  - 从赛事共享源移除
  - 管理违规或错误照片

关键原则：
“从我这里移除”只影响个人视图；
“从赛事里撤回/移除”才影响共享源。

## UI/UX pattern

- 破坏性赛事级动作放在 overflow/bottom sheet 的 destructive section，不与查看/分享并列。
- 个人移除文案明确“仅从你的相册中移除”。
- 赛事级撤回文案明确“其他参与者将无法再看到”。
- 对不可恢复动作提供确认；可恢复动作优先 Undo。
- 不仅靠红色区分权限和危险性，文案必须说明影响范围。

## Why it works

权限边界如果只存在于后端而不在 UI 中表达，用户仍会误解。成熟协作/共享产品都会把个人视图操作与共享源操作区分。

## Applicability to 球搭子

高，尤其是多人赛事、Club、共同相册等未来方向。若 V8 扩展照片贡献者角色，这一边界会更重要。

## Counterexample / Risk

- 普通参与者若根本没有 personal save state，则“从我这里移除”应删除，而不是保留一个无意义动作。
- 赛事管理员过多会引入权限争议。
- 若上传者撤回后其他人已保存到设备，系统无法“收回”设备副本，文案不能暗示彻底删除。

## Smallest validation

做两套 viewer：
A. 当前式动作；
B. 普通参与者只有分享/保存到设备，overflow 中仅在有权限时显示“从赛事中移除”。

另为有 personal state 的场景测试“从我这里移除”。
让用户预测每个动作对自己、其他参与者和设备副本的影响。

## What not to do yet

暂不做复杂角色矩阵、照片审批流、举报审核后台、版权水印治理等，除非真实需求出现。

## Open questions

- 谁拥有赛事源删除权限：上传者、Organizer、Club Admin？
- 上传者是否能在赛事结束后长期撤回？
- 删除赛事源后，历史 Match Memory 是否显示占位？
