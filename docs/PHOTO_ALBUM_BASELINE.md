# 球搭子｜赛事照片与参与赛事相册基线

> 日期：2026-08-30。状态：照片专项当前产品真源。与早期文档冲突时，以本文为准。

## 1. 两层相册模型

照片分为两层，但两层生命周期必须独立：

1. **赛事相册（source）**：属于赛事，仅由赛事创建人/组织者管理，是实际参赛者选择照片的来源。
2. **我的参与赛事相册（personal album）**：属于个人，只包含本人从自己实际参加过的赛事相册中主动选择并成功“加入我的参与赛事相册”的照片资产。

系统不得因为用户参加赛事就自动把全部赛事照片加入其个人相册。

关键规则：**加入成功后不再只是对 EventPhoto 的脆弱引用，而形成当前参赛者自己的受保护个人相册资产/快照。赛事源照片之后被组织者删除，不影响已经成功加入个人相册的照片。**

## 2. 权限拆分

### 赛事创建人 / organizer
- 是赛事相册唯一管理者。
- 赛事结束后可上传多张赛事照片。
- 可以删除自己赛事相册中的任一源照片。
- 删除只改变赛事源照片及其后续可获取性：删除后赛事页不再显示，也不能再被任何参赛者新加入个人相册。
- **不得因为删除赛事源照片而删除参赛者此前已经成功加入个人相册的独立资产。**

### 实际参赛者 / participant
- 可以查看自己实际参加赛事当前存在的赛事照片。
- 不能上传、替换或删除赛事源照片。
- 可以对当前仍存在的赛事照片执行“加入我的参与赛事相册”。
- 加入成功时由服务端校验 actual participant 身份，并形成该用户自己的受保护个人相册资产。
- 已加入后可以执行“移出我的参与赛事相册”；这只删除自己的个人相册资产，不影响赛事源照片或其他参赛者。
- 仅受邀但未形成有效 Entry 的用户不能获取赛事照片到个人相册。

### 普通 viewer / 非参赛者
- 公开赛事也不会因此公开赛事照片。
- 不得读取赛事照片或加入个人相册。

## 3. 赛事源照片删除模型

组织者只在赛事页面的赛事相册管理区执行：**删除照片**。

二次确认建议：

> 删除后，这张照片将从本场赛事相册中永久删除，其他参赛者也无法再从本场赛事获取它。已经加入自己“参与赛事相册”的照片不会受影响。此操作不可恢复。

删除必须由服务端重新校验赛事 owner 权限；前端不能通过任意 Storage path 删除对象。

删除赛事源照片时应清理该 EventPhoto 的源 metadata、源高清原图和源水印预览；但不得级联删除已经导入到 participant personal album 的独立副本。

## 4. 加入我的参与赛事相册

“加入我的参与赛事相册”应理解为**导入/保存到个人资产**，不是简单收藏引用。

服务端必须在导入瞬间校验：
- 当前 Profile 是该 Event 有效 Entry→Player 的 actual participant；
- 源 EventPhoto 当前仍存在且可访问；
- 同一用户对同一源照片不得重复导入。

导入成功后形成独立 personal album item。建议至少保存：
- owner_profile_id
- event_id / event_name / event_date 等必要赛事上下文快照
- source_event_photo_id（仅用于溯源，可在源删除后置空）
- 个人副本的 private original / protected preview 路径
- imported_at

`source_event_photo_id` 删除时应采用 `ON DELETE SET NULL` 或等价逻辑，禁止 `ON DELETE CASCADE` 删除个人资产。

源照片删除后：
- 未导入用户不能再获取；
- 已导入用户个人相册继续正常显示；
- 个人相册副本继续受个人相册权限保护。

## 5. 我的 → 参与赛事相册

“我的”页面保留一级入口：**参与赛事相册**。

这里只展示本人主动加入成功的个人照片资产，按赛事分组。

本人可以：
- 查看已经加入的照片；
- 移出自己的参与赛事相册；
- 回赛事相册继续选择当前仍存在的其他照片。

“移出我的参与赛事相册”只删除本人的个人副本，不影响赛事相册和其他用户。

## 6. 参与赛事相册隐私

“我的 → 设置与隐私”不承担赛事照片上传、编辑、删除管理。

这里只提供个人级别的：**参与赛事相册可见范围**。

当前两个值：
- `仅自己可见`（默认）
- `搭子可见`

设置作用于整个参与赛事相册；MVP 不要求逐张配置。

开启搭子可见不改变赛事本身隐私，也不给搭子赛事管理权。

## 7. 搭子查看边界

只有 accepted Connection 可以进入 TA 设置为“搭子可见”的参与赛事相册。

搭子侧：
- 只展示个人副本的受保护水印预览；
- 服务端重新校验 Connection + 目标用户 album visibility 后签发短时 URL；
- 列表接口不得下发 Storage object path；
- 不获得高清原图或赛事照片管理权。

个人相册本人可以查看自己的个人资产；是否开放本人个人副本高清可在后续产品迭代确定，MVP 至少保证受保护预览长期可用。

赛事上下文中的高清原图权限仍按 organizer / actual participant 的赛事授权执行，不能因为搭子可见扩权。

## 8. 数据模型原则

建议实体关系：

`Event -> EventPhoto (source)`

`Profile -> ParticipantAlbumItem (independent personal asset)`

ParticipantAlbumItem 可以记录 nullable `source_event_photo_id` 用于来源追溯，但其生命周期不得依赖源记录。

- EventPhoto 一场可多张；由 organizer 创建/删除。
- participant 导入必须复制/固化个人受保护资产，而不是只创建源引用。
- EventPhoto 删除不得删除 ParticipantAlbumItem；source FK 使用 SET NULL 或等价策略。
- participant 主动移出时才删除自己的 ParticipantAlbumItem 及对应个人 Storage 副本。
- personal album visibility 为 Profile 级偏好，默认 private。
- 赛事源和个人副本均保持 private Storage。

## 9. UI 术语

赛事页组织者：
- `上传照片`
- `删除照片`

赛事页参赛者：
- `加入我的参与赛事相册`
- `已加入`

我的参与赛事相册：
- `移出我的相册`

隐私设置：
- `参与赛事相册可见范围`
- `仅自己可见`
- `搭子可见`

不要把“删除赛事源照片”和“移出我的个人相册”混成同一种操作。

## 10. P0 验收

- 一场赛事可存在多张赛事照片。
- 只有 organizer 能上传和删除赛事源照片。
- participant 能看自己赛事当前照片，但不能管理赛事源照片。
- 系统不自动把赛事照片加入 participant 个人相册。
- participant 可逐张主动加入个人相册；非 actual participant 不可导入。
- 导入成功后形成独立个人受保护资产，而非仅保存源引用。
- organizer 删除源照片后：赛事页立即消失；其他尚未导入用户无法再获取；**已导入 participant 的个人相册照片继续存在且可用**。
- 源删除不得级联删除个人相册资产；源 FK 应 SET NULL 或等价处理。
- participant 可主动“移出我的相册”，只删除本人个人资产。
- 隐私设置只管理参与赛事相册整体 private / partners，不出现赛事照片删除管理入口。
- 默认仅自己可见；切换搭子可见后持久化。
- accepted partner 只能看目标用户主动开放个人相册的水印预览；非 Connection 无权。
- partner list 不下发 Storage path，partner 不获得高清。
- public/private event 不扩大赛事源照片读取权限。
- zh/en 与 375/390/430px 下赛事相册、加入操作、个人相册和隐私设置可用。
