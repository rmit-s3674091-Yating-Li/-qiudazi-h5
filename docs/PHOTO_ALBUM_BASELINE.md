# 球搭子｜赛事照片与参与赛事相册基线

> 日期：2026-08-30。状态：照片专项当前产品真源。与早期文档中“自动把赛事照片归入每个参赛者相册”“组织者从赛事页移除但后台继续给参赛者保留”“参赛者可删除赛事照片”等规则冲突时，以本文为准。

## 1. 两层相册模型

照片只分两层：

1. **赛事相册（source）**：属于赛事，由赛事创建人/组织者管理，是所有参赛者可选择照片的唯一来源。
2. **我的参与赛事相册（personal selection）**：属于个人，是本人从自己实际参加过的赛事相册中主动选择加入的照片引用。

系统**不得自动**因为用户参加了一场赛事，就把该赛事全部照片塞进其个人相册。

个人相册保存的是对赛事源照片的受控引用，不复制出一份脱离源照片生命周期的永久副本。

## 2. 权限拆分

### 赛事创建人 / organizer
- 是赛事相册唯一管理者。
- 赛事结束后可上传赛事照片；赛事相册允许多张照片。
- 可以删除自己赛事相册中的任一照片。
- 删除是赛事源照片的真实删除，不使用“从赛事相册移除”与“永久删除”两个近义按钮制造歧义。
- 删除后该照片立即从赛事页消失，也必须从所有参赛者的“参与赛事相册”引用中失效/移除。
- 参赛者不能阻止组织者删除赛事源照片。

### 实际参赛者 / participant
- 可以查看自己实际参加赛事当前仍存在的赛事照片。
- 不能上传、替换或删除赛事源照片。
- 可以对每张仍存在的赛事照片执行“加入我的参与赛事相册”。
- 已加入后可以执行“移出我的参与赛事相册 / 取消收藏”；这只删除自己的引用，不删除赛事照片，也不影响其他人。
- 仅受邀但未形成有效 Entry 的用户不是实际参赛者，不能使用上述能力。

### 普通 viewer / 非参赛者
- 公开赛事也不会因此公开赛事照片。
- 不得读取赛事照片或加入个人相册。

## 3. 删除模型

MVP 不同时提供“移除”和“永久删除”两套赛事照片管理动作。

组织者在赛事页照片管理区点击：**删除照片**。

二次确认应明确：

> 删除后，这张照片将从本场赛事相册中永久移除；已将它加入“参与赛事相册”的参赛者也将不再看到这张照片。此操作不可恢复。

删除必须由服务端重新校验赛事 owner 权限；前端不能传任意 Storage path 获得删除权。

赛事源 metadata 删除后，所有个人收藏引用必须依赖外键级联或等价服务端一致性机制失效；private Storage 中对应高清原图和水印预览必须进入同一删除流程。失败不得误报成功。

如果用户只是觉得某张赛事照片不想放在自己的个人相册，应使用“移出我的参与赛事相册”，而不是删除赛事源照片。

## 4. 我的 → 参与赛事相册

“我的”页面保留一级功能入口：**参与赛事相册**。

该页面只展示当前真实用户主动从实际参加赛事中加入的照片。

按赛事分组展示：赛事名称、比赛日期、本人已选择照片。

本人可以：
- 查看已加入照片；
- 移出自己的参与赛事相册；
- 返回对应赛事相册继续选择仍存在的照片。

如果赛事创建人之后删除源照片，该照片自动从本人的参与赛事相册消失，不保留脱离赛事源的副本。

## 5. 参与赛事相册隐私

“我的 → 设置与隐私”不承担赛事照片上传、编辑、删除管理。

设置与隐私仅提供个人级别的：**参与赛事相册可见范围**。

当前只有两个值：
- `仅自己可见`（默认）
- `搭子可见`

该设置作用于整个“参与赛事相册”，MVP 不要求每张照片再单独配置可见性。

开启“搭子可见”不改变赛事本身隐私，不代表照片中的其他人公开自己的相册，也不给搭子赛事管理权。

## 6. 搭子查看边界

只有 accepted Connection 可以进入 TA 设置为“搭子可见”的参与赛事相册。

搭子侧：
- 只展示受保护的水印预览；
- 预览必须经服务端重新校验 Connection + 目标用户相册 visibility + 源照片仍有效后签发短时 URL；
- 列表接口不得下发 Storage object path；
- 不获得高清原图访问能力；
- 不获得赛事照片上传、删除或个人收藏修改能力。

高清原图继续只允许赛事 organizer 与该赛事 actual participant 在赛事合法上下文中显式触发短时授权。

## 7. 数据模型原则

建议实体关系：

`Event -> EventPhoto (source)`

`Profile -> ParticipantEventPhotoSave -> EventPhoto`

其中 `ParticipantEventPhotoSave` 必须校验 Profile 是该 Event 的实际有效 Entry→Player participant。

- EventPhoto 可一场多张。
- EventPhoto 由 organizer 创建/删除。
- ParticipantEventPhotoSave 是个人收藏关系，不是图片副本。
- EventPhoto 删除时个人收藏关系 `ON DELETE CASCADE` 或等价一致清理。
- 个人相册 visibility 存在 Profile 级偏好中，默认 private。
- `event-photos` 保持 private。

## 8. UI 术语

赛事页组织者：
- `上传照片`
- `删除照片`

赛事页参赛者：
- `加入我的参与赛事相册`
- `已加入 · 移出我的相册`

我的页面：
- `参与赛事相册`

隐私设置：
- `参与赛事相册可见范围`
- `仅自己可见`
- `搭子可见`

禁止在同一层同时使用“移除赛事照片 / 删除赛事照片 / 删除我的照片”等容易误解的近义文案。

## 9. P0 验收

- 一场赛事可存在多张赛事照片。
- 只有 organizer 能上传和删除赛事源照片。
- participant 能看自己赛事当前照片，但不能上传/删除源照片。
- 系统不自动把所有赛事照片放进 participant 个人相册。
- participant 可逐张加入/移出“我的参与赛事相册”。
- 不是 actual participant 的用户不能收藏该赛事照片。
- organizer 删除源照片后，赛事页立即消失，所有 participant personal saves 同时失效；Storage 原图和水印进入一致删除流程。
- 删除失败不得误报成功，不得通过任意 path 删除他人对象。
- “我的”存在“参与赛事相册”入口并按赛事展示本人主动加入的照片。
- 隐私设置只管理“参与赛事相册”整体的 private / partners，不放赛事照片删除管理入口。
- 默认仅自己可见；切换搭子可见后持久化。
- accepted partner 只能看目标用户主动开放的参与赛事相册水印预览。
- 非 Connection、普通 viewer、仅 invited 用户不能读取搭子相册。
- partner list 不下发 Storage path，partner 不获得高清原图。
- public/private event 不扩大源赛事照片读取权限。
- zh/en 与 375/390/430px 下赛事相册、收藏按钮、个人相册和隐私设置可用。
