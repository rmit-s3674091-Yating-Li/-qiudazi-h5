# 球搭子｜赛事照片与过往比赛相册基线

> 日期：2026-08-30。状态：照片专项当前基线。本文与早期文档中“普通前端永久删除赛事照片”的规则冲突时，以本文及 PRD V6 §5.1 的最新规则为准。

## 1. 权限必须拆分
照片权限分为四类，不得混用：

1. **赛事照片上传/替换权**：仅赛事创建人/组织者。
2. **赛事页查看权**：组织者 + 有效 Entry→Player 中已关联真实用户的实际参赛者。
3. **赛事照片管理权**：仅组织者；参赛者有查看权不等于有删除/管理权。
4. **个人历史相册展示权**：每位实际参赛者只管理自己个人空间里的展示范围，不改变赛事照片本身，也不影响其他参赛者。

赛事 public/private 不扩大照片权限。

## 2. 组织者“删除”的真实语义
普通前端不再提供物理删除赛事照片的产品语义。组织者点击“从赛事相册移除”后：

- 当前赛事页立即不再展示该照片；
- 当前赛事照片记录转入历史归档；
- 高清原图和水印预览继续保存在 private Storage；
- 实际参赛者仍可在自己的“过往比赛相册”查看；
- 组织者后续重新上传新的赛事主合影，不得覆盖或清理已经归档的历史照片；
- 参赛者、搭子、普通 viewer、仅 invited 用户均无权执行赛事照片移除。

Storage 真正物理清理属于后续受控数据生命周期，不与赛事页移除动作绑定。

## 3. 我的 → 过往比赛相册
实际参赛者自动获得自己参加过赛事的历史照片访问资格，包括后来被组织者从赛事页移除的归档照片。

每个赛事相册默认：`仅自己可见`。

本人可改为：`搭子可见`。

该设置只作用于本人个人空间：
- 不公开整个赛事；
- 不代表照片中的其他参赛者也公开自己的历史；
- 不赋予本人上传、替换、删除赛事照片的权利。

## 4. 搭子可见边界
只有 accepted Connection 可以进入 TA 主动开放的过往比赛相册。

搭子侧：
- 只获得受保护的水印预览；
- 预览通过服务端重新校验 Connection + 目标用户相册 visibility 后签发短时 URL；
- 列表接口不得下发 Storage object path；
- 不获得高清原图访问能力；
- 不获得赛事照片管理能力。

组织者和实际参赛者仍可在自身合法场景中显式点击“查看高清”，由服务端重新校验后短时授权。

## 5. 存储与数据模型
- `event-photos` 必须保持 private。
- 当前赛事主照片与历史归档资产分离保存 metadata。
- 组织者移除时使用同一事件级串行化边界和 version 校验，禁止 stale 操作误处理新版本。
- `event_album_preferences` 按 `profile_id + event_id` 保存 `private / partners`。
- 历史归档表、偏好表不得直接开放给 anon/authenticated 做表级读写；由受控 RPC / Edge Function 执行业务授权。

## 6. P0 验收
- 只有 organizer 能上传、替换、从赛事页移除。
- participant 只能看，不能管理赛事照片。
- organizer 移除后 EventPage 无照片；Storage 原图/预览仍存在；participant 历史相册仍可看。
- organizer 移除后重新上传新主合影，不得抹掉历史归档。
- 我的过往比赛相册只包含自己实际 Entry→Player 参与过的赛事。
- 默认仅自己可见；本人可切换搭子可见并持久化。
- accepted partner 只能看到目标用户主动开放相册的水印预览。
- 非 Connection、普通 viewer、仅 invited 用户不能读取搭子相册。
- partner album list 不下发 Storage path；水印预览 URL 短时有效。
- partner 不能请求高清原图；organizer/participant 高清仍需显式授权。
- public event 不扩大上述权限。
- zh/en 与 375/390/430px 页面、按钮、相册切换和空状态可用。
